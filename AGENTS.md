# Lampwarden

A night-defence roguelite (Next.js App Router + Pixi via @pixi/react) whose sprites are generated by a model through
Mubit, rendered from code, verified and corrected. Built at the Mubit Night Shift hackathon, 24 Oct 2026.

Conventions come from the project-local skills in `.agents/skills/` (`project-structure`, `typescript-stack`,
`react-stack`, from frostney/known-good-route; `skills-lock.json` pins them, never hand-edit). Tooling and code style:
[docs/tooling.md](docs/tooling.md), [docs/code-style.md](docs/code-style.md). Architecture:
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Commands

- `bun install`, then `bun run dev`. Bun is the only package manager; `bun.lock` is the only lockfile.
- `bun run check` is the gate: Biome, TypeScript, `bun test`, Knip, `next build`.
- `bun run verify:visual -- --url http://localhost:3000` against `bun run build && bun run start`: the headed visual
  verifier. Run it and look at `verify-out/sheet.png` after every change that can show on screen.
- Rendering a sprite needs Vercel auth and a snapshot: `docs/tooling.md`, "Rendering needs Vercel auth".
- `bun run balance` plays nights headlessly; `bun run plays` reports from recorded plays (needs `vercel env pull`).

## Deviations from the skills

- Components are flat files in `src/components/` (no `atoms`/`molecules`/`organisms` folders): five components don't
  need the Atomic Design split. Add a folder only when a component grows companions (`Name.test.tsx`, `Name.types.ts`).
- No Tailwind, Clerk, Convex or Sentry/PostHog: plain CSS in `src/app/globals.css`, no accounts, recorded plays in
  Vercel Blob.

## Git and pull requests

Follow `.agents/skills/git-workflow` and `.agents/skills/create-pr` / `update-pr`. In short:
- Branch from the freshly fetched remote default; update a branch by merging its base, never rebasing. Never amend,
  never force-push. Pull requests are squash-merged, so the PR title is a Conventional Commit subject stating the
  impact.
- Run the publication guard (`python3 .agents/skills/git-workflow/scripts/publication_guard.py`) before each commit
  (`staged --message-file`), push (`outgoing --base origin/main`) and PR title/body write (`pr --repo
  frostney/lampwarden ...`). This repository is public.
- **Every pull request that changes anything a player or reviewer can see carries media**: before/after screenshots
  (the visual verifier's `verify-out/` shots are a good source) and, for behaviour, a short narrated video with burned-in
  subtitles. Upload with `gh pr create --attach` / `gh pr edit --attach`; never commit evidence media. Code-only
  changes attach the verifier contact sheet showing nothing moved.
- Make the video with `bun run walkthrough -- <script.ts> --url <server> --out <dir>` (`e2e/walkthrough.ts`): copy
  `e2e/walkthroughs/title.ts` to a script outside the repo, write one caption per segment, run it against a local
  build, and look at `<dir>/check.png` before attaching `<dir>/walkthrough.mp4`. `<dir>/stills/` holds each
  segment's last frame for the before/after shots.
- Write PR bodies with local file references (`![alt](./shot.png)`), run the publication guard on that file, then
  upload with `--attach`. Never run the guard on a body that already holds uploaded attachment URLs: GitHub serves
  `user-attachments` only to signed-in users, so the guard reads them as private references and rewrites the images
  away.

## Hard rules

- Never print, log or commit `MUBIT_API_KEY`, `BLOB_READ_WRITE_TOKEN` or any token (a Vercel OIDC token included).
  Read keys from the environment only; run `gitleaks git --redact .` before every push.
- Environment variables are declared in `.env.schema` (Varlock): name, type, where required, `@sensitive` for every key,
  token and salt. Read them through `ENV` from `varlock/env` in server code, or from the environment a `varlock run`
  script gets; never add a variable without declaring it, never put a value in `.env.schema`, and keep local keys in the
  git-ignored `.env.local` as `exec()` or `keychain()` references (docs/tooling.md, "Environment"). Pipeline scripts get
  only the variables they `--filter`; model-written code never gets any.
- Every Mubit call goes to `https://api.mubit.ai/anthropic/v1/messages` with model `claude-opus-5-5`; never send
  `temperature`.
- Model-generated build code runs only in Vercel Sandbox.
- The repository has no Python of its own: scripts are TypeScript run with Bun, and types are shared between them.
- Pixel art is made by code that lives in this repo (kit builders, `tools/logo`, `src/scene/projectiles.ts`,
  `src/components/Icon.tsx`). Don't commit hand-made or externally generated images.
- `pipeline/kit/` is the model-facing sprite API: its names (`k`, `S`, builder params) are what prompts and committed
  sprite scripts use, so it is excluded from Biome and the naming rule. `kit.ts` is generated by `bun run kit`.
- The game's sim is deterministic (seeded RNG, fixed 60 Hz step); recorded plays replay from inputs. Keep randomness
  inside `rand(state)` and input through the controls/driver path, or replays break.
- `.agent/` holds local handoff state and is git-ignored.
